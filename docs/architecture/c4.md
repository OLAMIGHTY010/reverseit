## Event flow (D2)

```mermaid
sequenceDiagram
    participant H as Handler (API or worker)
    participant PG as PostgreSQL
    participant R as Outbox relay
    participant RS as Redis Stream
    participant C as Consumer

    H->>PG: BEGIN
    H->>PG: write state change
    H->>PG: INSERT outbox_events
    H->>PG: COMMIT
    loop every poll interval
        R->>PG: select unpublished rows (advisory lock, in order)
        R->>RS: XADD each row
        R->>PG: mark published
    end
    C->>RS: XREADGROUP / XAUTOCLAIM
    C->>PG: BEGIN, insert processed_events(event_id)
    alt event_id already processed
        C->>RS: XACK (duplicate skipped)
    else new
        C->>PG: handler writes, COMMIT
        C->>RS: XACK
    end
    Note over C,RS: handler error: no ack, redelivered after the idle time<br/>too many deliveries: copied to the .dlq stream and acked
```

Delivery is at least once. A crash between `XADD` and marking the row published sends the event twice, and `processed_events` makes the second delivery harmless. If Redis loses a stream, `outbox.Requeue` marks rows unpublished and the relay sends them again.
